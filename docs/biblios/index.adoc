== Einleitung

Das Themenrepo ist der fachliche Vertrag zwischen Datenportal, Jenkins-Plugin und GRETL-Builds. Es beschreibt, welche Organisationen am Datenportal teilnehmen, welche Datensätze publiziert werden können und mit welchen Defaults die generierten Jenkins-Jobs ausgeführt werden. Gleichzeitig werden im Themenrepo auch die Metadaten zu einem Datenthema verwaltet.

Der Vertrag ist unabhängig vom Ausführungsmodus: Im produktiven Workflow wird ein Git-Stand verarbeitet. Die lokale Jenkins-Entwicklungsumgebung kann zusätzlich einen `working-tree`-Snapshot mit uncommitteten Änderungen verwenden. Dieser technische Modus ändert weder den Vertrag noch die Inhalte des Themenrepos.

Diese Doku richtet sich an Themenintegratoren und Entwickler. Sie erklärt nicht primär, wie Datenlieferanten eine Datei hochladen, sondern wie das Repository aufgebaut sein muss, damit das Jenkins-Plugin daraus valide Jobs, Startformulare und Ausführungslogik erzeugen kann.

=== Was gehört in diese Dokumentation?

Diese Dokumentation beschreibt:

* die erwartete Struktur des Themenrepos;
* die Marker-Dateien für Organisationen und Datensätze;
* die Bedeutung von `gretl-datenportal-job.yaml`;
* die Auflösung von `shared/Jenkinsfile` und organisationsspezifischen Jenkinsfiles;
* den Gradle-Build-Vertrag zwischen Themenrepo und Jenkins;
* Maintainer-Workflows für neue Organisationen, neue Datensätze und Seed-Läufe.
* das Zusammenspiel mit Offline-Bundle, Java 17 und Java 21;

=== Was gehört nicht in diese Dokumentation?

Nicht behandelt werden hier:

* fachliche Anleitung für Datenlieferanten;
* Bedienung des Anlieferformulars aus Endnutzersicht;
* Betrieb des Jenkins-Controllers im Detail;
* Entwicklung des Jenkins-Plugins selbst.

== Kurzfassung

Das Themenrepo ist keine lose Dateisammlung. Es ist ein maschinenlesbarer Vertrag. Das Jenkins-Plugin scannt das Themen-Repository, erkennt valide Organisationen und Datensätze, wendet Berechtigungen und Defaults an und materialisiert daraus Jenkins-Jobs.

Eine Organisation ist ein Top-Level-Ordner mit gültiger `gretl-datenportal-job.yaml`. Ein Datensatz ist ein Unterordner einer Organisation mit genau einer `.xtf`- oder `.xml`-Datenblattdatei (= Metadaten zum Thema). Das Startformular ist fix und kann nicht konfiguriert werden.

Der angenommene Lieferstand liegt in den durch S3-`current.json` bezeichneten
Gesamt-XTF. Git verwaltet Code und einzelne Datenblätter; automatisches
Git-Rückschreiben betrifft ausschliesslich das ausgewählte Datenblatt.
