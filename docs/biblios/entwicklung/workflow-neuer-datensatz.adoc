= Neuen Datensatz anlegen
:page-layout: docs
:toc: macro
:toclevels: 2

== Ziel

Ein neuer Datensatz soll einer bestehenden Organisation hinzugefügt werden.

== Minimaler Ablauf

. Datensatzordner unter der Organisation anlegen.
. Genau eine `.xtf`- oder `.xml`-Datenblattdatei in den Ordner legen.
. Optional `dataset.gradle` ergänzen, wenn der Datensatz eigene Gradle-Build-Logik benötigt.
. Änderungen committen und auf dem produktiv verwendeten Branch bereitstellen.
. Seed-Job erneut ausführen.

Für lokale Plugin-Entwicklung kann die Änderung im `working-tree`-Modus vor dem
Commit getestet werden. Das ist ein technischer Snapshot der Dev-Umgebung und
ändert nicht die fachliche Versionierungsregel für den produktiven Ablauf.

== Beispiel

[source,text]
----
afu/
└── ch.so.umwelt.neuer_datensatz/
    └── ch.so.umwelt.neuer_datensatz.xtf
----

== Mit datensatzspezifischem Build-Override

[source,text]
----
afu/
└── ch.so.umwelt.neuer_datensatz/
    ├── datenblatt.xml
    └── dataset.gradle
----

Der Dateiname der Datenblattdatei ist frei wählbar. Ihr Element `identifier`
muss jedoch `ch.so.umwelt.neuer_datensatz` entsprechen.

`dataset.gradle` wird vom gemeinsamen Gradle-Skript nur für den ausgewählten
Datensatz geladen. Es darf Build-Logik ergänzen, ändert aber keine Jenkins-
Job-Konfiguration, Startformular-Felder, Berechtigungen oder Datensatzerkennung.

== Datensatzserie

Wenn das Datenblatt eine `DatasetSeries` beschreibt, zeigt das fixe Startformular zusätzlich `SERIES_ID` an. Dieses Verhalten wird aus dem Datenblatt abgeleitet und nicht über eine separate YAML-Konfiguration gesetzt.

== Häufige Fehler

[cols="1,2",options="header"]
|===
| Fehler | Folge

| Keine `.xtf`- oder `.xml`-Datei im Datensatzordner
| Der Datensatz ist ungültig.

| Mehr als eine `.xtf`- oder `.xml`-Datei im Datensatzordner
| Der Datensatz ist mehrdeutig.

| Erwartung zusätzlicher Formularfelder aus dem Datensatzordner
| Nicht unterstützt.
|===
