== Erkennung

Ein Datensatz ist ein Unterordner einer Organisation mit genau einer Datenblattdatei. Die Datenblattdatei muss die Endung `.xtf` oder `.xml` haben.

[source,text]
----
afu/
  ch.so.umwelt.beispiel/
    ch.so.umwelt.beispiel.xtf
----

oder:

[source,text]
----
statistikdienst/
  ch.so.bevoelkerung.beispiel/
    datenblatt.xml
----

Der Scanner erwartet pro Datensatzordner genau eine solche Metadatendatei. Mehrdeutige oder fehlende Metadatendateien sind Validierungsfehler.

== Datensatzserie

Ob im Startformular `SERIES_ID` angezeigt wird, wird aus dem Datenblatt abgeleitet. Das Feld erscheint, wenn die Metadaten im Datenblatt eine Datensatzserie beschreiben, also wenn das Root-Objekt `DatasetSeries` ist.

== Optionales `dataset.gradle`

Ein Datensatzordner kann optional eine Datei `dataset.gradle` enthalten.

[source,text]
----
afu/
  ch.so.umwelt.beispiel/
    ch.so.umwelt.beispiel.xtf
    dataset.gradle
----

`dataset.gradle` ist ein Build-Override. Die Datei wird nur geladen, wenn der Datensatz zur Laufzeit ausgewählt wurde. Sie eignet sich für datensatzspezifische Zusatzlogik, zusätzliche Properties oder abweichende Build-Hinweise.

`dataset.gradle` erzeugt keinen eigenen Jenkins-Job, ändert keine Startformular-Felder und ersetzt keine Organisationskonfiguration.

== Technische Unterordner

Nicht jeder Unterordner einer Organisation ist automatisch ein Datensatz. Technische Unterordner können ignoriert werden, wenn sie nicht wie Datensatzordner aussehen. Ordnernamen, die wie Datensatz-IDs aussehen, aber keine `.xtf`- oder `.xml`-Datenblattdatei enthalten, werden als Fehler behandelt.

== Empfehlung für Namensgebung

Der Ordnername sollte der fachlichen Datensatz-ID entsprechen.

[source,text]
----
ch.so.abfall.deponien/
ch.so.bevoelkerung.wohnbevoelkerung/
ch.so.gewaesser.messstellen/
----

Die Datenblattdatei darf technisch anders heissen. Für Lesbarkeit und Fehlersuche ist es aber sinnvoll, denselben Namen wie den Ordner zu verwenden.
