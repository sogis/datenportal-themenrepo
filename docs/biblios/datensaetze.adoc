= Datensätze
:page-layout: docs
:toc: macro
:toclevels: 2

== Erkennung

Ein Datensatz ist ein Unterordner einer Organisation mit genau einer Datenblattdatei. Die Datenblattdatei muss die Endung `.xtf` oder `.xml` haben. Der Dateiname der Datenblattdatei ist frei wählbar. Entscheidend ist, dass genau eine `.xtf`- oder `.xml`-Datei vorhanden ist und deren Element `identifier` dem Namen des Datensatzordners entspricht.

[source,text]
----
agi/
└── ch.so.agi.beispiel/
    └── ch.so.agi.beispiel.xtf
----

oder:

[source,text]
----
statistikdienst/
└── ch.so.bevoelkerung.beispiel/
    └── datenblatt.xml
----

Der Jenkins-Plugin-Scanner und die gemeinsame Gradle-Logik erwarten pro Datensatzordner genau eine solche Metadatendatei. Mehrdeutige, fehlende oder inhaltlich nicht zum Ordner passende Metadatendateien sind Validierungsfehler.

== Datensatzserie

Ob im Startformular `SERIES_ID` angezeigt wird, wird aus dem Datenblatt abgeleitet. Das Feld «Ausgabe» erscheint und wird verpflichtend, wenn das Root-Objekt `DatasetSeries` ist und eine Datendatei ausgewählt wurde. Reine Metadatenlieferungen benötigen keine Ausgabe.

== Optionales `dataset.gradle`

Ein Datensatzordner kann optional eine Datei `dataset.gradle` enthalten.

[source,text]
----
agi/
└── ch.so.agi.beispiel/
    ├── ch.so.agi.beispiel.xtf
    └── dataset.gradle
----

`dataset.gradle` ist eine optionale datensatzspezifische Gradle-Erweiterung. Sie wird nicht vom Jenkins-Plugin geladen, sondern von `shared/gradle/organisation-common.gradle`, wenn der Datensatz über `-Pdataset` ausgewählt und erfolgreich aufgelöst wurde.

Die Datei kann zum Beispiel datensatzspezifische Gradle-Tasks oder Build-Konfiguration registrieren. Für den gemeinsamen Kontext steht ein Override-Hook zur Verfügung:

[source,groovy]
----
project.ext.datenportalDatasetOverride = { context ->
    context.extraGradleProperties['datasetProfile'] = 'beispiel'
    context.summaryLines << 'Datensatzspezifisches Profil aktiviert.'
}
----

Zusätzliche Properties und Summary-Zeilen werden vom gemeinsamen Build-Kontext und vom erzeugten Ausführungs-Report bereitgestellt. Eine Property verändert den eigentlichen Publikationsablauf nur dann, wenn ein Gradle-Task sie auch auswertet.

`dataset.gradle` erzeugt keinen eigenen Jenkins-Job, ändert keine Startformular-Felder, Berechtigungen oder Datensatzerkennung und ersetzt keine Organisationskonfiguration.

== Technische Unterordner

Nicht jeder Unterordner einer Organisation ist automatisch ein Datensatz. Technische Unterordner können ignoriert werden, wenn sie nicht wie Datensatzordner aussehen. Ordnernamen, die wie Datensatz-IDs aussehen, aber keine `.xtf`- oder `.xml`-Datenblattdatei enthalten, werden als Fehler behandelt.

== Empfehlung für Namensgebung

Der Ordnername sollte der fachlichen Datensatz-ID entsprechen.

[source,text]
----
ch.so.abfall.deponien/
ch.so.bevoelkerung.wohnbevoelkerung/
ch.so.gewaesser.messstellen/
----

Die Datenblattdatei darf technisch anders heissen. Für Lesbarkeit und Fehlersuche ist es aber sinnvoll, denselben Namen wie den Ordner zu verwenden.
