== Grundsatz

Das Startformular ist fix. Es wird nicht mehr aus YAML- oder Datensatzkonfiguration im Themenrepo zusammengesetzt.

== Unterstützte Felder

[cols="1,3",options="header"]
|===
| Feld | Bedeutung

| `ORGANISATION`
| Aus den gültigen Organisationen im Themenrepo abgeleitet.

| `DATASET`
| Aus den erkannten Datensatzordnern und Datenblättern der Organisation abgeleitet.

| `PUBLICATION_MODE`
| `delivery`: «Lieferung verarbeiten» (Default), mindestens eine Upload-Datei. `repository-metadata`: «Datenblatt aus Repository übernehmen», ohne Upload.

| `RELOAD_PORTAL`
| «Portal nach Veröffentlichung neu laden», Default aus; Reload nach erfolgreicher S3-Übernahme, sofern administrativ konfiguriert.

| `METADATA_FILE`
| Upload-Feld für Metadaten.

| `DATA_FILE`
| Upload-Feld für Daten.

| `COMMENT`
| Freitextkommentar zur Lieferung.

| `SERIES_ID`
| Ausgabe innerhalb einer `DatasetSeries`, z. B. `2025`. Das Freitextfeld erscheint bei Auswahl einer Datendatei und ist dann verpflichtend; noch nicht erfasste Ausgaben sind zulässig.
|===

Beim Entfernen der Datendatei oder Zurücksetzen des Formulars wird die Ausgabe
geleert, ausgeblendet und deaktiviert. Ohne JavaScript bleibt das Feld
zugänglich; die bedingte Pflicht wird serverseitig geprüft.

Eine reine Metadatenlieferung aktualisiert das gesamte Datenblatt und benötigt
keine Ausgabe. Ein dennoch gesetztes `SERIES_ID` wird nicht an Gradle
weitergereicht. Direkte Gradle-Aufrufe ignorieren `-PseriesId`, wenn
`-PdataFile` fehlt. Im Modus `delivery` bleibt mindestens eine Upload-Datei
erforderlich. `repository-metadata` leert und deaktiviert Uploads und Ausgabe;
technisch trotzdem übermittelte Uploads werden serverseitig abgewiesen.
Diese Regeln gelten auch ohne JavaScript und für direkte Gradle-Aufrufe.
Organisationsrechte bleiben für beide Modi gleich. Die Publikationsfreigabe
ist eine administrative Einstellung und kein zusätzliches Formularfeld.

== Keine GUI-Konfiguration im Themenrepo

Das Themenrepo kann keine zusätzlichen Formularfelder definieren.
